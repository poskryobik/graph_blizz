# 0016 — Leased PostgreSQL worker для indexing jobs

## Status

Accepted

## Context

Indexing должен выполняться отдельным процессом, а несколько экземпляров worker
не должны одновременно владеть одной job. Процесс может завершиться между
получением job и записью результата, поэтому одного статуса `RUNNING` недостаточно.

## Decision

Worker атомарно переводит одну доступную `PENDING`/`RETRY` job в `RUNNING` через
`FOR UPDATE SKIP LOCKED`, записывает owner и ограниченный lease, а heartbeat
продлевает lease только для того же owner. Истёкшие leases возвращаются в
`RETRY` либо завершаются `FAILED`, если попытки исчерпаны.

При SIGTERM/SIGINT worker прекращает новый claiming и даёт текущему indexing
завершиться. Если контейнер принудительно остановлен раньше, job остаётся под
lease и затем восстанавливается другим worker. Обработка имеет семантику
at-least-once; запись результата job дополнительно защищена owner и живым lease.
На время processing worker удерживает session-level PostgreSQL advisory lock по
`document_id`. Новый владелец может восстановить и claim-ить истёкшую job, но
начинает внешнюю мутацию только после выхода предыдущего execution. Переходы
состояния документа проверяют `job_id`, owner, номер attempt и живой lease,
поэтому запоздалый cleanup потерявшего lease владельца не меняет документ.
Если процесс успел перевести точную активную ревизию документа в `READY`, но не
записал успех job, повторная обработка распознаёт этот терминальный результат как
идемпотентный успех и завершает job через тот же owner/lease fence без повторной
вставки документа.

## Consequences

Можно безопасно масштабировать worker горизонтально без центрального диспетчера.
Длительная операция требует регулярного heartbeat и отдельного PostgreSQL
соединения на время processing. После аварии повторный запуск откладывается до
истечения lease; разрыв соединения освобождает advisory lock. Внешние
storage-вставки должны терпеть повторное выполнение после аварии процесса.

## Alternatives considered

- In-process background task API: связывает жизненный цикл HTTP и indexing.
- Только PostgreSQL advisory lock без lease: не даёт наблюдаемого состояния,
  heartbeat и управляемого retry после аварии.
