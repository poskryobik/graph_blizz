# 0020 — Версионированные пространства индекса

## Status

Accepted

## Context

Изменение parser/chunk/index schema или embedding-модели делает существующие
derived-данные несовместимыми. Обновление индекса на месте смешало бы в одном
пространстве векторы и граф, построенные по разным контрактам.

## Decision

Workspace хранит текущие `index_schema_version` и identity embedding-профиля,
а каждая document revision — parser/chunk/index versions и признак
`requires_reindex`. При смене workspace-контракта существующие ревизии
атомарно помечаются для reindex. Физический LightRAG namespace включает digest
активного контракта, поэтому новые записи не попадают в прежний индекс.

## Consequences

Несовместимые данные нельзя случайно смешать, а исходные объекты остаются
доступны для будущего durable reindex. Старое derived-пространство не удаляется
автоматически и требует отдельной процедуры очистки после успешного reindex.

## Alternatives considered

- Обновлять индекс на месте: не обеспечивает однородность embeddings и schema.
- Немедленно удалять старый индекс: ухудшает восстановление при сбое миграции.
