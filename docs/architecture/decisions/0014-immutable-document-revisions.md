# 0014 — Неизменяемые ревизии документов

## Status

Accepted

## Context

Demo хранит логический документ и его source-объект в одной строке `documents`.
Для обновления содержимого нужен стабильный `document_id`, последовательные номера
ревизий и возможность переключать активную версию только после успешной обработки.
Существующие документы и их source-объекты нельзя потерять или перезаписать.

## Decision

Логическая идентичность и состояние остаются в `documents`, а неизменяемые
`object_uri` и `content_hash` переносятся в `document_revisions`. Новые object keys
содержат номер ревизии; `documents.active_revision` указывает на активную запись,
а добавление ревизии сериализуется блокировкой строки документа и выдаёт следующий
номер монотонно. Существующие строки мигрируют в ревизию 1 с прежним `object_uri`.

## Consequences

`document_id` не меняется при обновлении source, а каждая версия имеет отдельный
неизменяемый объект. Текущий Demo API продолжает получать `object_uri` и
`content_hash` из активной ревизии. Добавление ревизии требует транзакции и
блокировки логического документа; старые object keys сохраняют прежний формат,
поскольку перенос объектов между ключами не является операцией SQL-миграции.

## Alternatives considered

- Оставить ревизии колонками `documents`: не позволяет хранить историю версий.
- Перезаписывать один object key: нарушает неизменяемость и мешает recovery.
- Перенести существующие объекты в migration: Alembic не должен зависеть от MinIO.
