# 0007 — Qdrant connectivity boundary

## Status

Accepted

## Context

Demo-контур использует Qdrant как векторное хранилище. Инфраструктура должна
проверять готовность сервиса и сохранять данные между пересозданиями контейнера,
а application code — уметь проверить соединение без публикации отдельного HTTP
API для управления Qdrant.

## Decision

Qdrant запускается как зафиксированный Compose-сервис с named volume и
опубликованным web/API-портом. Внутренний синхронный adapter инкапсулирует
официальный Qdrant client, проверяет соединение через чтение списка коллекций и
преобразует ошибки клиента в стабильную ошибку storage boundary.

## Consequences

Данные переживают пересоздание контейнера, web UI доступен разработчику с host,
а прикладной код не зависит от деталей ошибок клиента. Клиент необходимо явно
закрывать; публичный application endpoint для Qdrant не появляется.

## Alternatives considered

- Проверка через произвольный HTTP client: не выбрана, чтобы runtime-проверка и
  дальнейшая интеграция использовали один официальный клиент.
- Новый FastAPI endpoint: не выбран, потому что Qdrant доступен напрямую через
  опубликованный Compose-порт, а публичный application API не требуется.
